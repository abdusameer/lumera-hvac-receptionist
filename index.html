Technical view

Behind the call

The caller only hears a conversation. Underneath, each request follows a fixed, testable path.

Request path

  1. Voice agentHolds the conversation and calls a tool when it needs data.
  2. WebhookReceives the tool request.
  3. Request abstractionReads the tool name and its arguments into one consistent shape.
  4. Tool routingSends the request to one of three paths.

Tool routing · three paths

Check availability

  1. Receive the customer's requested date.
  2. Retrieve existing Google Calendar events.
  3. Combine the request with calendar availability.
  4. Generate valid appointment times.
  5. Return available slots to the voice receptionist.

Book appointment

  1. Receive the customer's name and chosen appointment time.
  2. Create the Google Calendar event.
  3. Send a booking confirmation.
  4. Return the successful booking result to the voice receptionist.

Qualify lead

  1. Capture the service type.
  2. Capture the reported HVAC problem.
  3. Determine urgency.
  4. Structure the lead information for follow-up.

What the prototype does

Only what the workflow shows.

Voice-call handling
Answers and holds a short, structured conversation.
Intent routing
Sends each request to availability, booking or qualification.
Calendar availability checks
Reads existing events and offers only open times.
Appointment scheduling
Creates the calendar event for the chosen time.
Confirmation messages
Sends the booking confirmation by email.
Lead qualification
Captures service type, problem and urgency.
Structured handoffs
Gives the team an organized record, not a voicemail.
Workflow monitoring
Each run can be reviewed to see which step completed or failed.
